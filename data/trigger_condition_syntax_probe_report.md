## 一、本轮做了什么

上一轮报告只对每种规范时机测了**一个标准写法**（例如"受到伤害前"只测了这一
个字符串）。本轮针对用户"补充触发条件的标准语法，测试各种触发条件能否正常
触发"的要求，做了两件事：

1. **在 `自创法术语法.md` 里补充了完整的识别规则表**（关键词组合、判定优先级、
   排斥条件、剥离修饰词列表），把"为什么某句话能/不能被识别成某个规范时机"讲
   清楚，而不只是给几个例句。
2. **对全部11种规范时机，每种时机穷举3~7种常见同义写法**（合计42种具体写法），
   分三层实测：
   - **解析层**：`parse_trigger()` 是否把同一组同义写法都归一到同一个规范时机；
   - **已接线3种时机的真实触发层**：换用不同同义写法学法术，是否都能在真实
     `resolve_monster_phase` 结算里触发生效（不是只测解析结果字符串对不对，
     而是连带资源变化数字一起验证）；
   - **未接线8种时机的诚实标注层**：换用不同同义写法学法术，是否都正确标注
     `wired=False` 并附带warning（不会因为换了个说法就被误判成"已接线"）。
   - 额外覆盖12组边界/歧义写法（空输入、裸词缺前后缀、未知词汇、"前后"同现
     的歧义句子、"敌"字与其它关键词共存的干扰样例）。

## 二、触发条件标准语法（摘要，完整版见 `自创法术语法.md` 1.1节）

判定分两步：**①剥离修饰词**（我方/自身/对方/己方/自己的/时/的/（循环）/(循环)）
→ **②按优先级顺序匹配关键词组合**，命中第一条满足条件的规则即返回该规范时机。

| 优先级 | 规范时机 | 命中条件 | 排斥条件 |
|---|---|---|---|
| 1 | 敌回始 | 含"敌" 且 含（"回合开始"/"回始"） | 无 |
| 2 | 敌回终 | 含"敌" 且 含（"回合结束"/"回终"） | 无 |
| 3 | 回始 | 含"回合开始"/"回始"/"每回合开始" | 原文不能含"敌" |
| 4 | 回终 | 含"回合结束"/"回终"/"每回合结束" | 原文不能含"敌" |
| 5 | 战始 | 含"战斗开始"/"战始"/"开局" | 无 |
| 6 | 战终 | 含"战斗结束"/"战终"/"结局" | 无 |
| 7 | 目标发动道纹前 | 含（"发动道纹"/"使用道纹"/"出招"/"发动法术"）且含"前" | 无 |
| 8 | 受到伤害前 | 含（"受到伤害"/"受伤"/"承伤"/"受到攻击"）且含"前" | 无 |
| 9 | 受到伤害后 | 同上关键词组 且含"后" | 无 |
| 10 | 失去生命前 | 含（"失去生命"/"损失生命"/"掉血"/"扣血"/"生命减少"）且含"前" | 无 |
| 11 | 失去生命后 | 同上关键词组 且含"后" | 无 |

裸词缺"前/后"（如只写"受到伤害"、"生命减少"）会被直接拒绝，因为无法判断
是哪个结算点；完全不认识的词汇、空输入同样直接拒绝。

### 3.1 边界/歧义写法（12组）实测

| 写法 | 期望行为 | 实测结果 |
|---|---|---|
| 空字符串 / 纯空白 | 拒绝 | ✅ 拒绝："触发条件不能为空" |
| "受到伤害" / "受伤" / "生命减少"（裸词缺前后缀） | 拒绝 | ✅ 拒绝："无法识别触发条件" |
| "乱写一通" | 拒绝 | ✅ 拒绝 |
| "敌方受到伤害前" | 识别为"受到伤害前"（不应被"敌"字误伤成敌回合系列） | ✅ 正确识别 |
| "战斗开始后" / "回合开始前" | "前后"对战始/回始无区分意义，仍按核心词命中 | ✅ 正确识别为战始/回始 |
| "受到伤害前后" / "失去生命前后"（前后同现的病态写法） | 按规则表顺序命中排在前面的那条（受到伤害前/失去生命前） | ✅ 与文档描述一致（**建议不要这样写，属于歧义写法，引擎不会报错提醒，会静默按前者理解**） |
| "敌方发动道纹前" | 命中"目标发动道纹前"（因为满足"发动道纹+前"，不满足敌回合系列的"回合开始/结束"关键词） | ✅ 正确识别，非敌回合系列 |
