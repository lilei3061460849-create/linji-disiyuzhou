# 长期记忆角色完整经历：顾砚舟与岩行者

> 这是一份独立的角色案例报告，不是 `报告.md` 的待解决问题。`报告.md` 只保留未解决/待裁定事项，已经结案的旧战报不再混在那里。
>
> 本案例使用真实 `GameEngine` 的开局、事件、回始、队友指令和 `use_daowen` 管线。每次行动均由 `GameEngine.execute_action()` 校验并落地；数值取自引擎返回值。为了把组合链条清楚地展示出来，战斗构筑中的道纹是在受控测试夹具中注入当前角色的，不把这段短报告冒充成自然七场通关记录。
>
> **阅读标记**：`【引擎事实】` 指 API 返回、实体状态或事件正文中实际发生的内容；`【顾砚舟主观】` 指角色的情绪、记忆和自我解释；`【作者解释】` 指报告作者对组合为何成立的分析。没有标记的过渡句只负责连接叙事，不替代引擎证据。

## 一、【顾砚舟主观】他是怎样的人

**顾砚舟｜seed=4｜名字检索确认未与仓库既有角色重名**

他的长期记忆在进入轮回时这样写下自己：

- **身世**：曾是龙心谷边缘村落的守夜人，亲眼看过同伴被龙火带走；
- **遗憾**：明明看见危险，却因为犹豫错过了出手时机；
- **价值观**：活下来比证明自己勇敢更重要；
- **恐惧**：活着，却逐渐认不出自己；
- **目标**：让至少一个同行者安全离开这一轮。

这不是一个“只要伤害数字最大”的角色。他害怕再次来不及救人，因此会把“谁承担代价、谁留下来”看得和输出一样重要。他也不是圣人：他的选择会让别人受伤，而且他知道这一点。

## 二、完整经历：从守夜人到共同负债者

### 1. 开局：他没有拿到最安全的答案

【引擎事实】顾砚舟用 `seed=4` 开始一阶轮回，属性点分配为：

```text
血点9 / 速点4 / 法点12
血限54 / 速限2 / 法限6
```

【引擎事实】引擎列出的开局遗物候选是：

```text
回锋刀 / 血契 / 买路财
```

他选了 **血契**。

【作者解释】血契不是单纯的资源遗物。它要求有人和他共同承担流血代价，也意味着他的每一次“换法力”都可能把队友拖进同一笔债里。初始道纹候选是：

```text
增殖 / 贯穿 / 庇护
```

他选了 **庇护**。【顾砚舟主观】这不是因为他已经确定自己是求稳者，而是因为他不想让第一次错误重演：看到危险，却没有来得及留下退路。

### 2. 龙心谷事件：他选择接过伤者

【引擎事实】进入龙心谷后，顾砚舟遇到真实事件【断桥余烬】。

熔岩断桥上，一个微光者背着失去行动能力的同伴，铁索正在烧断。顾砚舟可以绕桥，也可以拿走遗物，但他选择了：

> **接过伤者。**

引擎实际返回：

```text
流血10
岩行者作为朋友加入
顾砚舟生命：54 → 44
```

岩行者不是报告作者临时取的名字，而是事件正文和 `engine/events.py` 真实创建的友方实体：

```text
岩行者：2×4 / 54
持有道纹：【背负1】
```

【作者解释】这一步把顾砚舟的目标变成了现实关系：他不再只是口头上“希望有人活下来”，而是用自己的生命换来了一个具体的同行者。

### 3. 受控构筑：把过去的恐惧变成一条危险的连锁

为了验证长期记忆角色能否通过道纹、遗物和队友形成真正的组合，本次受控战斗为顾砚舟加载了：

```text
自身道纹：逆鳞、加害、裂变、血债
遗物：血契
队友：岩行者（背负1）
敌人：引擎真实抽取的石背熊（血限252，2×7）
```

这里的“受控”只指构筑预先给定；行动结果没有手算替代引擎。敌人的攻击、友方的承伤、道纹代价、状态叠加和最终生命全部由 API 落地。

## 三、两回合的组合破局

### 第一回合：血契供能，逆鳞立债，加害改写未来

#### 回始：遗物先把两个人绑在一起

【引擎事实】顾砚舟向血契提交 `X=4`，明确指定岩行者分担代价。

引擎返回：

```text
血契：流血16，与岩行者共同承担，+4法力
```

这不是“免费法力”。这笔法力的来源是两个人一起失去生命：血契把资源优势直接转换成关系成本。

#### 轮回者命令队友

【顾砚舟主观】顾砚舟没有让岩行者自主行动，而是通过真实接口提交：

```text
command_ally(friend:0, "护卫 2")
```

【引擎事实】引擎返回成功：岩行者将在接下来的两次针对顾砚舟的命中中承担伤害，而且这条护卫命令不消耗岩行者本轮的出手。

【作者解释】这不是“队友站在旁边被动挨打”。这是顾砚舟主动要求岩行者替他承担风险；岩行者接受了，但代价会真实落在岩行者身上。

#### 逆鳞：顾砚舟把自己的生命押进下一次伤害

【引擎事实】顾砚舟对石背熊发动【逆鳞 X=4】，并指定岩行者共同承担代价。

```text
流血4：顾砚舟支付2，岩行者支付2
石背熊获得【逆鳞4】
顾砚舟当前生命：36 → 34
```

这一步没有立刻制造大数字。它是在敌人身上埋下一笔“下一次伤害会变重”的债，同时证明顾砚舟愿意把代价和队友共同承担，而不是把所有风险都写成自己的英雄主义。

#### 加害：不是现在杀死，而是让之后的每一击都更危险

【引擎事实】顾砚舟发动【加害 X=1】。

```text
消耗3法力
石背熊获得永久【加害1】
```

此时他手里已经没有多少法力，却没有选择招架，也没有立即输出。他选择先把敌人的受伤规则改掉。

#### 怪物阶段：岩行者兑现承诺

【引擎事实】石背熊发动两次7点攻击。顾砚舟没有再闪避，岩行者的【背负】承接了这两次攻击。

引擎结果显示：

```text
顾砚舟在本轮后保持34点生命
岩行者承担了实际伤害
顾砚舟没有因为保存自己而取消队友的代价
```

第一回合结束时，顾砚舟没有“无伤赢下回合”。他只是把死局变成了一个还能继续的局面：自己还活着，岩行者也还在，敌人身上留下了可继续利用的状态。

### 第二回合：裂变铺轨，血债收束

#### 回始：再次使用血契

【顾砚舟主观】第二回合，顾砚舟再次选择血契 `X=6`。

```text
血契：流血24，与岩行者共同承担，+6法力
```

这一次的决定更危险。顾砚舟已经不是满血，岩行者也不是满血；如果这一轮只换来一次失败的尝试，两个人都会因为“共同承担”而一起接近命零。

#### 裂变：把一次命中拆成多次结算

【引擎事实】顾砚舟发动【裂变 X=2】：

```text
消耗6法力
石背熊获得永久【裂变2】
之后受到的伤害改为分2次结算
```

他把全部法力几乎都押在了一个尚未发生的伤害上。此时他已经没有足够资源再靠招架补救。

#### 血债：三次伤害把前面的状态串起来

【引擎事实】最后，顾砚舟发动【血债 X=3】。

血债的原始数值是：

```text
流血3
3次伤害
原始总伤害3
```

引擎实际返回：

```text
顾砚舟支付流血2
岩行者支付流血1
石背熊 raw_damage=3
石背熊 actual_damage=6
石背熊生命：252 → 246
```

此时石背熊身上的状态是：

```text
逆鳞4 / 加害1 / 裂变2
```

顾砚舟没有凭空声称“组合造成了6点伤害”。`use_daowen` 的 `execution.effects` 明确返回了 `raw_damage=3` 和 `actual_damage=6`。

## 四、这段经历的结局

两回合结束时，引擎状态是：

```text
顾砚舟：生命44 → 20，法力归零
岩行者：生命54 → 17，仍然存活
石背熊：生命252 → 246，仍然存活
```

这不是一个“顾砚舟两回合清场”的假英雄故事。他没有赢得战斗，只赢得了继续行动的资格；岩行者也没有毫发无伤，只是没有倒下。

【作者解释】真正的破局点是：

- 血契把两人的生命变成共同资源；
- 背负把敌人的两次攻击转移给愿意同行的人；
- 逆鳞把生命代价转成后续伤害势能；
- 加害提高每次受伤的收益；
- 裂变为多段结算铺路；
- 血债在队友共同承担的前提下完成收束。

顾砚舟没有把岩行者当作一次性肉盾，但他确实把岩行者置于危险中。这种关系才有继续发展的空间：下一场，岩行者可能更信任他，也可能认为他把“共同承担”用到了过火的地方。

## 五、顾砚舟会记住什么

这次经历适合被写进他的长期记忆的，不是“我曾经招架过一次”，而是：

> **“血契不是把代价消失掉，而是让另一个人愿意和我一起承担。岩行者替我接住了两次攻击；下一次轮到他站在火里时，我不能只把他当成我的退路。”**

这条记忆会给他留下两个互相拉扯的倾向：

- 他更相信共同承担确实能破局；
- 他也更害怕把同伴消耗成自己的工具。

后续是否继续使用血契、是否让岩行者再次护卫、是否转向保护队友，应该由下一次真实行动和真实结果决定，而不是由报告替他提前写死。

## 六、规则正文核对：友方指挥此前确实没有写清楚

是的，之前正文存在缺口。

正文原来只写了两件事：

1. [朋友]/[员工]会根据情况自主对敌方出手；
2. 龙心谷道纹【背负】可以让目标承担伤害。

但它没有明确写出：**轮回者可以通过 `command_ally` 主动命令已部署的朋友/员工攻击、发动自身道纹或执行护卫。**

这个机制此前主要存在于：

- `engine/api.py` 的执行实现；
- `engine/ai_player.py` 的可用动作 schema；
- `AI_EXPERIENCE.md` 的手操经验和代码说明；
- `tests/test_guard_command.py` 等测试。

因此用户只读正文时确实很难知道“轮回者可以命令友方角色”。我已经把它补进 `AI_EXPERIENCE.md` 的 **第四宇宙规则正文·基础定义**，明确了：

- `攻击 <敌方名>` / `打 <敌方名>`；
- `发动 <道纹名> [打/对 <目标>]`；
- `护卫 [X]` / `保护我 [X]` / `挡伤 [X]` / `替我挡 [X]`；
- 护卫不消耗友方出手，X 是命中次数而不是回合数；
- 目标非法、友方死亡/撤退、未部署或未持有道纹时由引擎拒绝，不能产生部分效果。
