### 真实伤害链与预演

敌对伤害会先预演一次受击调整供濒死保护判断，随后正式扣血时再计算一次。两者是两份独立 `DamageResolutionContext`：分别标为 `preview` / `commit`；预演不改实体、不提交生命变化，也不会被误记成第二次正式伤害。规则 ID 在同一 context 内最多执行一次；延后事件仅排队，不递归进入当前链。

## 3. 统一执行结构

### 事实源与执行路径

`engine/rule_engine.py` 中的 `DaoWenRuleDefinition` / `DamageRuleDefinition` 明确记录：稳定 ID、触发事件与阶段、目标角色、条件组、读写字段、最新值读取语义、运算符、参数来源、缺省值、priority 后备、代价、持续期及描述渲染。`DaoWenEngine.calculate_*` 的摘要和 `sim/gen_daowen_index.py` 的索引条目均读取这些定义。

现有 Mechanism/Hook API 没有删除：三条机制仍通过 `MechanismHookAdapter` 挂在 `CombatHookManager.apply_incoming_adjust` 的唯一伤害分发链上；适配器不再自带第二份数值公式。`Entity.take_damage` 的直接调用（未传入状态调整器）仍保留固执旧兼容分支；正式 CombatEngine 路径传入统一调整器，因此不会双算。

### 可组合运算与扩展点

通用 `apply_operator` 已提供 ADD、SUBTRACT、MULTIPLY、DIVIDE、MIN、MAX、CLAMP、SCALE_PERCENT（显式取整）、CONVERT、DEFER、CUSTOM。条件支持 ALL/ANY/NOT、状态/伤害类型/事件标签及值比较。复杂效果可以注册 CUSTOM 运算器；DEFER 只写入待处理事件，不在当前规则链递归分发。当前生产道纹只使用 ADD、SUBTRACT+下限和 MIN，不在注册表中写组合配方。

### 可解释日志字段

伤害返回值新增：

- `damage_resolution`：攻击者、受击者、原始/上游/当前/规则后/倍率后伤害、伤害类型、格挡吸收、HP 前后和 preview/commit context；
- `rule_trace`：正式结算每一步的 rule ID、阶段、目标、读取字段和语义、运算符、参数、before/after、条件和自然语言解释；
- `preview_rule_trace`：保护预演的独立规则记录；
- `actual_life_loss`：真实生命值差。

`DAMAGE_APPLIED` 事件一并携带两类 trace 与实际生命损失。trace 只含稳定标识、字符串和有限整数，严格 JSON 编码测试使用 `allow_nan=False`。

## 4. 组合行为的涌现证明

下列数值由独立定义、同一执行器与既有状态排序自然得出；引擎没有 `固执+龙鳞` 组合分支：

1. 同 X、【固执】先施加：输入 5 → 固执 `min(5,1)=1` → 龙鳞 `max(0,1-1)=0`；倍率前规则结果 0，实际失血 0。
2. 同 X、【龙鳞】先施加：输入 5 → 龙鳞 `max(0,5-1)=4` → 固执 `min(4,1)=1`；实际失血 1。只改变状态施加顺序就改变结果。
3. 发动 X 覆盖施加顺序：即使固执先创建，龙鳞 X=2 大于固执 X=1，仍先执行；输入5 → 龙鳞3 → 固执1。
4. ADD 验证中间 0 不短路：龙鳞 X=8 先把输入8减为0；后续加害读取当前0并加2，结果2，而非重读原始8。
5. 阶段语义验证：固执先将受击当前值5压到1；【第一杯】随后把待扣值翻倍至2，最终失血封顶再将其压回1。故最终实际失血上限由规则和实现共同保证。

对应断言见 `tests/test_guzhi_longlin_combo.py` 与 `tests/test_daowen_rule_engine.py`，同时覆盖 trace 次序、X 排序、状态施加顺序、格挡、代价、预演/提交隔离、重复执行保护与大数/无效输入。
