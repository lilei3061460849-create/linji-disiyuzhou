## 2026-08-21 规则变更（已落实，引擎与正文同步）

### 1. 平分规则（新增·基础定义）
当一个数值同时作用于多个目标时，若要求平分，则将该效果的总数值在所有目标之间平均分配；无法整除时，余数按随机数分配（引擎 `DiceEngine` 随机源，可复现）。除非效果另有说明，多目标不会复制或增加效果的总数值。
- 实现：`CombatEngine._divide_flat(total, count)`（`engine/combat.py`）。
- 影响：血契代价拆分与波及扩散数值分摊都走这条规则。

### 2. 冲击改名波及（道纹体系变更）
- 【波及X】：消耗3X。选择X个[目标]建立/解除波及效果，持续∞。你发动的道纹同时作用于所有拥有波及效果目标；数值平分（按平分规则）。
- 波及标记是 `StatusEffect(name="波及", remaining_rounds=-1, source=施法者名)`：[战终]随局内状态清除；再次选择同一目标为**解除**标记（toggle，`CombatEngine._toggle_wave_mark`）。
- 扩散口径（2026-08-21 用户裁定）：所有道纹均可扩散；数值类效果（伤害/回复/格挡/血限/攻面板增减/速度增减等，见 `WAVE_NUMERIC_KEYS`）**总数值平分**，余数随机；状态类效果（束缚/眩晕/减速减半/固定面板/持续状态等）对波及目标**原样生效**。
- 扩散目标 = 本次[目标] + 拥有施法者波及标记的存活角色，均排除施法者自身；不产生新闪避判定，但**波及X本身选择X个目标时逐目标显式提交闪避**（与旧冲击同款 dodge_targets 协议：玩家侧 `use_daowen`，怪物侧 prepare/resolve 两阶段）。
- 数值修正顺序：先按原公式算总数值 → 逆鳞/借力/坠落修正 → 再平分。百分比类（百分比失血/百分比回复/瓦解）先按各目标面板求总值再平分。

### 3. 血契描述修改
- 数值型代价可与一名存活的朋友或员工**平分**（原"你承担向上取整一半"作废）；余数按随机数分配。[回始]可流血4X获得X法力，本次流血也可平分。
- 实现：`CombatEngine.validate_numeric_cost` 改用 `_divide_flat(amount, 2)`。

### 4. 封印道纹改为代价
- 【封印X】：代价：异变8X。使X个[目标]怪物移出本场战斗（被移出的怪物不提供碎片收益）。
- 怪物侧发动封印照常支付异变8X（`_resolve_monster_daowen_choice` 专属分支），支付后崩解按统一死亡管线结算。

### 7. 死斗规则及程序（新增）
1. 死斗按阶级进行：挑战者只能与自身副本阶级的封存候选死斗；每个阶级封存槽是**先来后到队列**（2026-08-21 用户裁定：同阶槽排队），挑战者依次与队首死斗。
2. 通过死斗的角色进入**进阶封存**：一阶死斗胜者进入二阶封存槽，以此类推；进阶封存后不得再与原阶级角色重复死斗（如通过一阶死斗进入二阶封存后，不得再与一阶角色死斗）。
3. 死斗败者失去轮回者身份，触发【死之传承】。
- 实现：封存文件格式改为 `{"candidates": {"1": [快照…], "2": [快照…]}}`；兼容读取旧版单快照文件（视为一阶槽队首）。`GameState.sealed_candidates` / `duel_tier` 同步持久化；`_trigger_final_crown`（按 `REGION_TIERS` 查本阶级槽）、`_finalize_victory_seal(advance_tier)`（胜者 +1 阶封存）、`handle_resolve_final_duel`（终音法器选择后仍封入进阶槽）。

## 真实测试阶段策略：残韵解锁副本专属道纹闭环（2026-08-21 起）

### 核心规则：学习门槛（README《局外系统·学习门槛》第237行）

> 当前副本的专属道纹须先通过残韵从本副本怪物处转化获得至少一种，此后才可学习该副本的其它专属道纹；其它副本专属道纹不可学习。怪物转化道纹只能从自身已持有道纹经残韵变化获得，原始怪物道纹无法由人类学习。

**精确语义（引擎事实源 `engine/api.py::_pre_battle_xuexi.daowen_error`，测试 `tests/test_region_daowen_gate.py`）：**

1. **资格判定只看持有，不看来源**：玩家已持有当前副本专属集合中**任意一种**，即可经局外【学习】逐种习得该副本其余全部专属道纹；错误信息「须先经残韵获得本副本一种专属道纹后才能学习」。
2. **解锁的唯一合法途径就是残韵转化**（开局发现池只含杀伐闭环11节点、局外学习被同一门槛挡住、转化道纹/原始怪物道纹不可学习，三者封死其它路径）。
3. **解锁动作发生在战斗内**：`use_resonance` 是战斗行动（可任意时刻插队、不消耗出手），局外没有"转化"按钮——对持有本副本专属道纹的怪物发动残韵，该怪物道纹被永久改写为同闭环相邻节点，施法者同时永久获得变化后道纹（X 值按施法者自由控X自定义，不继承怪物数值）。
4. **闭环保证必然解锁**：扭曲都市/罪孽都市/龙心谷/乱葬岗四条专属闭环均为8节点闭合环，任何针对专属道纹的残韵只会落到**同一副本**的另一专属道纹，故一发动即满足门禁。
5. 局外【学习】道纹档位：1种=0碎片/1精力，2种=10碎片/1精力（法术档位1/2/3=0/10/25碎片）。

### 各副本专属道纹清单（`engine/gamedata.py::REGION_EXCLUSIVE_DAOWEN`）

- 扭曲都市：变形、定型、畸变、僵化、超频、坏死、爆裂、退化
- 罪孽都市：洗劫、逼债、抵扣、清算、赎金、假钞、赌命、消灾
- 龙心谷：加害、龙鳞、逆鳞、活血、裂变、嫁祸、背负、伤痕
- 乱葬岗（二阶，同样适用）：分裂、尸爆、缄默、瓦解、冥气、勾魂、镇尸、招魂

### 真实测试实战策略

1. **战始即规划残韵目标**：怪物面板与道纹在[战始]即公开，优先锁定持有本副本专属道纹的怪物；残韵类型（转换/反转/曲解）开局自选，领悟可继续补充储备（尤其是反转/转换，见既有「残韵对策战术」）。
2. **优先解锁，再学闭环**：每场只有3点精力，解锁后应尽早用【学习】补齐与 build 契合的专属道纹（单种0碎片），不要空耗精力修行。
3. **警惕改写的副作用**：怪物失去源道纹、获得新道纹，威胁形态会当场改变（例如把怪物的【自愈】改成【寄生】会改变它的回血手段）；改写怪物道纹同时是削弱手段与解锁手段，一次动作双重收益。
4. **同魂笔放大器**：持有【同魂笔】时一次残韵可另选一[目标]使其一种道纹受同种残韵影响（两份改写），但施法者获得的变化后道纹仍保持唯一。
5. **禁区**：不要浪费时间尝试学习其它副本专属道纹、怪物转化道纹或原始怪物道纹——引擎一律拒绝（跨副本错误信息明确）。
6. 真实测试战绩与道纹表现按《报告.md》口径记录（边际胜率/选择率/遭遇胜率），旧模拟数据已作废（见 2026-08-21 规则变更节）。



## 2026-08-22 版本变更与实战经验沉淀（【波及】目标数限制 + 怪物阶段可恢复性 + 知识库更新协议）

### 1. 道纹的 X 必须受合法目标数限制（【波及】BUG-01 根因）
- 怪物侧：`prepare_monster_phase` 中【波及X】的合法目标（存活、可被选中、非自身）不足 X 时，该道纹**不进入 daowen_options**——prepare 不得给出永远无法结算的选项。
- 玩家侧：`use_daowen` 的 X 上限（`_max_legal_daowen_x`）在法力/代价之外，再按存活非自身角色数封顶；朋友/员工固定 X 的【波及】在目标不足时 `available=False` 并给出原因。
- 提交协议不变：【波及】必须显式提交**恰好 X 个**不重复目标的 dodge_targets（玩家侧 `use_daowen`，怪物侧两阶段）；候选全量提交（候选>X）会被拒绝，AI/驱动一律用 `pick_wave_dodge_targets`（恰好 X 个、对侧优先）。

### 2. 怪物阶段失败必须可恢复（BUG-02 根因）
- 提交失败 = 状态整体回滚（零副作用）+ **token 保持有效**，同一 token 修正后重交即可；所有失败/拦截路径返回 `recoverable` + 当前有效 `token` + 可执行 `instruction`（`resolve_attack` 同构）。
- 仅当 prepare 快照跨回合失效时回滚 pending 并把子阶段还原为 player_actions。
- 同族问题一并修复：怪物**没有任何合法攻击目标**（如 solo 对手飞行而怪物不飞）时 `base_attack_actions=0`，本回合不出手——prepare 不得给出无法满足的出手义务。

### 3. 实体运行时属性禁止存活实体引用（RecursionError 根因）
- 【嫁祸】`_jiahuo_target` / 【背负】`_beifu_target` 原存活 Entity 引用：自施或互指形成引用环，事务回滚 `_restore_state_in_place` 的递归无限深入（学习遥测 4 次 RecursionError）。
- 现统一存 `runtime_id`（字符串），hook 按 id 解析实体。教训：`Entity` 的运行时属性（`_xxx`）只存标量/字符串，需要目标时按 `runtime_id` 解析（`ScopedStatDelta` 同款口径）。

#### 2026-08-22「迭代卡死两小时」根因与修复（sim/build_learner.py）
症状：让 agent 续跑/自迭代知识库，进程看似无声卡死两小时以上。四条叠加根因：
1. **真实死循环**：`play()` 能量 `while e.state.energy > 0` 无步数上限；一旦存在悬而未决的发现/雇佣选择，api 门禁（engine/api.py:830-840）会拒掉**一切**局外行动并退还精力（含兜底修行），能量永不减少、循环永不退出（实测原地打转 20 万步）。修复：每轮迭代开头 `_resolve_pending_choices` 先清门禁 + 连续 `STALL_LIMIT=5` 步精力不退即按无效局回收；`_resolve_pending_event` 事件链加 20 环上限。
2. **无声进度（观感卡死）**：stdout 重定向到管道时 Python 块缓冲，每代一行的进度全部憋在缓冲区，进程被超时杀掉后一行不剩（实测跑 20 秒 10 代全无输出，磁盘却已推进）——看起来像完全卡死，其实在前进。修复：每代 print 加 `flush=True`；跑批建议仍用 `python3 -u` 或重定向到文件后 `tail -f`。
3. **入口地雷**：docstring 教的 `python3 sim/build_learner.py` 必炸 `ModuleNotFoundError: tests`——`from tests.setup_support import ...` 写在 `sys.path.insert` 之前（sim/ 下 25 个脚本同病）。已全部按"sys.path 先行"重排，直接运行恢复正常。
4. **采样退化（质量问题）**：`main()` 调 `propose` 不传 region → 副本专属纹全被过滤，候选池恒定只剩 11/62 个道纹，知识库越迭代越同质。修复：按 REGIONS 轮转 propose+fitness 同副本评估，副本专属纹（抵扣/爆裂/畸变/赎金/逼债/消灾等）开始获得真实样本。
迭代防卡清单：跑批命令 `timeout 1800 python3 -u sim/build_learner.py --generations N --runs 10 --random-seeds | tee /tmp/bl.log`；无效局看 telemetry 的 `stalled`/`invalid_reasons` 键。
